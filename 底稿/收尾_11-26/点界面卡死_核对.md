# 点界面卡死、往上翻显示出错：核对（11-26）

玩家在群里说（电脑上玩，F12 没有报错）：“点界面就卡死”“卡死后点什么都没反应”，不止山铜纪；“日常界面上移导致网页显示出错”。截的是同行页（立绘卡带艺术照、战斗装两个钮）和底座面板。

## 一、结论

元凶是样式里认“每一条回复”的那个前缀 `@L@`：

```
div[style*="contain: layout"]:has(.sz-hud):not(:has(div[style*="contain: layout"]))
```

它认的是平台虚拟列表的行，靠行内 style 属性里的 `contain: layout` 认。可行的 style 属性正是虚拟列表一直在改的东西：挂上一行、卸掉一行、哪一行变高变矮，所有行的 `top` 都重写一遍。祖先那一格认 style 属性、底下挂着六十多条规则（页签、地名牌、三条、分支……），浏览器没法细分，只好每改一回就把所有挂着的回复整棵重算样式。

- 往上翻：每挂、卸一条回复，所有挂着的回复整棵重算。12 条时一次两秒上下（本机），40 条时一次十九秒。真页面上同时挂着的只有四五行，可每翻一屏就挂卸一次，慢一点的电脑一次就是一两秒。这段时间里虚拟列表量到的行高是旧的，行就叠在一起、跳来跳去，这是“上移显示出错”。
- 点界面：点页签、点艺术照、展开推演，那一条回复变高变矮，虚拟列表跟着改所有行的 top，又是一次全部重算。连着点几下，几秒的重算排着队，看上去就是“点什么都没反应”。不报错，因为这里没有脚本，全是样式。
- 你的猜想里“:has() 挂在大祖先上”是对的，但大头不在 body、.custom-styles 那几条（量过，去掉它们挂一条只从 87ms 降到 19ms），在“认行的 style 属性”这一条。动画、滤镜、阴影量下来不是卡点：空闲两秒样式重算 70 到 150ms，前后没变。

第二个小毛病：队友浮栏有一条“旧回复里不出”（`行:has(.sz-hud):has(~ div .sz-hud) .sz-pf{display:none}`），靠“后头还有带状态栏的行”认旧回复。这条同样认行的 style 属性，还认兄弟，点一下页签样式重算多出三倍。更糟的是窄屏（900px 以下，浮栏在正文顶上占一排）往上翻时，最新那一条被虚拟列表卸掉，上一条就不算旧回复了，浮栏冒出来，那一条高出 52px，列表跟着跳；跳回去又可能把最新那条挂回来，浮栏又藏起来。这是 history_far.py 11-07 修过的“来回跳”，11-22 的浮栏又带了回来。

## 二、量法

复刻台照 rili_bench 的页面结构（行带 `contain: layout style; position:absolute; top`，列表 `contain: size style`），拿 `tools/dryrun/runs/` 五局十五条回复轮着拼 N 条，末一条固定是山铜纪雨城清查第三轮（同行页有人、有艺术照）。样式用线上那份 `aldran_972a914d3893.css`（作用域过的，跟图床上同一份）。页面里挂一个 ResizeObserver 照行高重排 top，跟平台的虚拟列表一样会改行的 style。无头 Chrome，CDP 真点（鼠标按下抬起），等两帧，记墙钟和 Performance.getMetrics 的样式重算、排版时长。先载一回热字体再量。“挂一条新回复”是往列表头上插一行再卸掉，模拟往上翻时虚拟列表挂卸。

脚本都在会话临时目录（会清掉，要留的话照这里重写）：`scratchpad/lag/measure.mjs`（量）、`variant.py`（一样一样关掉做实验）、`xform.py`（把这一回的改动照字面套到线上那份样式上，做出改后的整份）、`tab.py`（出表）、`imgdiff.py`（逐像素比截图）。

## 四、一样一样关掉的实验（12 条，本机）

## 七、还没解决的

1. 根上那几条 `:has`（`.custom-styles:has(#conversation)`、`:has(.sz-hud)`、输入栏闲着认 `:focus`、`:placeholder-shown`，输入栏往上每一层 `:is(div,form):has(textarea)`）。全去掉的话挂一条回复还能从 82 降到 19ms，可单拿掉哪一类都降不下来，要一起换写法；它们管着整个大框的外壳、四纪的变量、输入栏的收放，动起来面太大，这一回没动。眼下修后挂一条是五六十到九十毫秒，可以先看真页面上够不够。
2. 立绘放大那一条（`*:has(.sz-zoom[open])`）：任何 details 开合都整棵重算挂着的回复，修后 6 条时推演一点 86ms。要省得换掉“点开时放开每一层祖先的 contain”这个做法（比如改用不受 contain 关着的弹层），牵涉显示正则，没动。
3. 往上滚动时最长的一帧 90 到 100ms，修前修后一样，样式和排版只占几毫秒，多半是重绘（外壳 ::before 上十层背景跟着滚动时间线动，两扇带 filter:drop-shadow）。复刻台没量绘制，没往下查。
