# DLC 切包：技术那一半（11-24，方向稿）

用户想把不影响整体的内容型条目从本体卡里摘出来，做成日里的“卡片专用模组”（免费，玩家自己装，世界书追加到本体）。这一份管切包：量、引用扫描、打包怎么接、发布设置、切完本体多大。只读，卡和源稿一个字没动。

底子：现行卡 `out/发布卡_四纪大框/奥尔德兰_四纪大框.json`（11-24 打的，世界书 8593 条，条目合计 39.93MB，紧凑重写一遍 40.24MB，跟 `分批导入/清单.json` 的 final_card_bytes 一样，显示正则 404 条）。探针结论见 CLAUDE.md「日里模组探针（11-24）」。

## 结论先说

- 主推切四包加一个附件：**羁绊篇**（540 条 2.97MB）、**支线**（216 条 1.66MB，连带只给支线用的史诗战对手 15 条 0.02MB）、**神谱**（216 条 0.82MB）、**大图书馆书目**（31 条 0.13MB）。合计 1018 条 5.60MB。
- 引用扫描：四包合切，本体里会落空的硬引用 **41 处，出在 35 条本体条目里**，都是“照X那一条”“（年份，X纪·支线｜Y）”这种指路的话，指不到也不坏事，模型只拿到一个名字。羁绊、大图书馆两包是 0。
- 本体切完 **7575 条、34.64MB**（少 5.60MB，约 14%），显示正则照旧 404 条，提示词、样式、介绍页不动。34.6MB 正好落在平台存过的最大一张（35MB 上下）以内。

## 二、引用扫描

`tools/refscan.py`，只读：

```
python -I -X utf8 底稿/DLC/tools/refscan.py <卡.json> 羁绊 支线 神谱 大图书馆 羁绊+支线+支线配套史诗战+神谱+大图书馆 [--show 60] [--out 明细.json]
python -I -X utf8 底稿/DLC/tools/refscan.py <卡.json> --folder '^57·' --title '^大图书馆｜'    # 临时挑一堆
```

空格隔开的各扫各的，`+` 连起来的算一回一起切（顺带查跨包）。十来秒一遍。这一回的输出存在 `refscan_11-24.txt`，明细 `refscan_明细_11-24.json`。

查什么（标题＝条目正文头一行去 #）：

- **硬引用（会落空）**：本体正文、主提示词、前置词、后置词里的「X」、……X那一条、直接写出的条目全名，X 是切出去那一条的全名、去掉纪名的“类｜名”、｜后头那一截（三个字以上）、标题里「」中的名字，或者整个切出去的文件夹名；本体也有同名条目的不算。本体条目的触发词和黑名单里写着切出去那一条的名字的，另列。
- **软提及**：切出去那一堆的专名（羁绊的“X之章”、支线｜后头的事名、神名、书名《X》）在本体正文里出现、本体又没有以它为题的条目。不落空，只是模型手里只剩一个名字。
- **反向**：切出去的条目引到同一回另一包的；切出去的有没有常亮的（触发 `/^/`）；靠 §预载 叫醒的有几条。

### 结果

| 包 | 硬引用 | 出在几条本体条目 | 本体触发里认它们 | 软提及（专名／出现在几条本体条目） |
|---|---|---|---|---|
| 羁绊 | 0 | 0 | 0 | 534 个章名／594 条（旅伴条、凡世至强条的“专属羁绊：X之章【题】”那一行，还有一两处地点条的“照X之章·Y”） |
| 支线 | 43 | 39 | 0 | 77／126（多是寻常话撞上事名，可以不管） |
| 支线＋配套史诗战 | 28 | 24 | 0 | 72／113 |
| 神谱 | 13 | 11 | 3（地点、战役条的触发里有神名，不碍事） | 131 个神名／938 条（04 的七十二魔神谱、纪元钟、凡世至强里都点名，各有一句来历） |
| 大图书馆 | 0 | 0 | 0 | 78 本书／146 条（人物条的“著作”那一行） |
| **四包合切（连配套史诗战）** | **41** | **35** | 3 | 815／1781 |

四包合切没有跨包引用，切出去的条目没有常亮的，也没有靠 §预载 叫醒的。

**那 41 处是什么**（逐条在 refscan_11-24.txt 末尾那一节）：

1. 迷宫纪史诗战对手三条（繁荣、深井、黑潮的年月）里五个对手后头括号写着“（年份，迷宫纪·支线｜X）”。这三条一条装了一整页的对手，不能跟着走；括号里指不到，对手和阶段名号照旧都在。
2. 地点、城邦、势力条里“某年那一回照X纪·支线｜Y”二十一处（月银纪地点七、纷争纪地点三和城邦一、山铜纪地点四、号墙两处、图鉴一、势力一、迷宫纪迷宫一、传奇一）。没装支线，那一回的事模型照地点条自己的话写。
3. 默娜、玛丽贝尔两条人物条指「迷宫纪·支线｜内森的地窖·最后一圈」。这条是暗线的收口之一，**建议这一条留在本体**（packs.json 的 keep_titles 加一行就行），切完支线硬引用再少两处。
4. 神谱十三处：纷争纪史诗战对手“魔神甲”几条括号里的“（年份，纷争纪·神谱｜X）”八处，射主、盾碑两条主线，穴镇、轰狱、白烛与接骨堂。魔神的名号、阶段、陨落年份在史诗战条和七十二魔神谱里都有，落空只少了神域栏那一层。盾碑那一处写的是“照人物举盾者斯卡索那一条”，现在本来就指不准（卡里没有叫这个的人物条，只有神谱条），顺手可以在源稿里改成神谱的全名。

这些都不用为切包改源稿。要更干净，下一轮洗稿时把“照X纪·支线｜Y”改写成一句那一回的事（照写作口径「出处」那一条：要用的事实写进句子），refscan 再跑一遍看数。

**软提及里要留意的一件**：旅伴条的“专属羁绊：X之章【题】”。没装羁绊篇，模型看得见章名、看不见那一章，可能自己编一章。各纪的「规则｜羁绊」写明了“这一纪的局里 1001 年那套羁绊总则不醒，由这一条顶上”，所以这四条规则跟着羁绊篇走（不装就不开章，只照主提示词记好感）。要防编，可以在本体一条四纪都醒的规则里添一句“专属羁绊那一行只是章名，那一章的条目没醒就不开章，只当这个人有一段还没讲的旧事”，装了 DLC 的局里那一章照样醒，不冲突。这一句属于创作层的改动，等用户点头。

## 三、打包：在打卡流程末尾加一步 make_dlc.py

### 现在的先后（存档「11-17 机械瘦身」第 8 条加 11-22 的 css_cdn）

v12 `build_v12.py` → `make_four_era_card.py`（主提示词、预载、拆幕、瘦身的模拟都在这一步里核完）→ `css_cdn.py` → 拷成 `_原介绍页.json` → `make_thin.py` → `into_card.py` → `split_card.py` → `zip_cards.py`。

### 插在哪

**into_card.py 以后、split_card.py 以前**：

```
python -I -X utf8 底稿/DLC/tools/make_dlc.py out/发布卡_四纪大框/奥尔德兰_四纪大框.json [--also out/发布卡_四纪大框/奥尔德兰_四纪大框_原介绍页.json] [--ver 11-24]
```

放这里的缘故：make_four_era_card 里那几回模拟（预载、拆幕、瘦身、主提示词）是拿整张卡跑的，切包放在它后头不碍那几回核；split_card 拿到的已经是本体，分批导入跟着变小，zip_cards 不用改（它只核介绍页跟 thin.html 是同一份，本体的介绍页没动）。

### make_dlc.py 做的事（待写，照下面的规格）

1. 读 `tools/packs.json` 挑条目（选法跟 refscan.select 同一套）。各包两两不相交，有重的就停。
2. **全本留底**：输入那一张原样拷成 `奥尔德兰_四纪大框_全本.json`（不发给玩家，风月版、1001 年切片和往后对账都从它出）。
3. **本体**：把选中的条目从世界书里拿掉，别的字段一个不动，写回 `奥尔德兰_四纪大框.json`（split_card、zip_cards 照旧读这个名字）。`--also` 给 `_原介绍页.json` 那一张同样切一刀，不然那一张里还带着 DLC 的条目，装了 DLC 会重两份。
4. **DLC 文件**：一包一份，写在 `out/发布卡_四纪大框/DLC/奥尔德兰DLC_<包名>_<版本>.json`。样子照这一回导得进、醒得对的探针（`out/探针_模组_11-24/模组探针.json`）：`{"title", "description", "language": "zh", "prompt": {"lorebook": [...]}}`，条目原样（优先级、深度、触发范围、黑名单、文件夹名一个不改），只带世界书。支线配套史诗战并进支线那一份。
5. **后置词默认不带**。探针只证明了模组的后置词会生效，没证明它跟本体的后置词是并在一起还是把本体的盖掉；本体后置词里管着底座的样子，盖掉就坏了。要带一两句（比如“专属羁绊那一章醒了才开章”），先另做一回探针：装了带后置词的模组以后，回复的底座那一行还在不在。
6. **核**：
   - 本体加各包合起来跟全本一条不多一条不少（拿 split_card.norm 比）。
   - 本体过 split_card.check_card，每条 DLC 条目过 check_entry。
   - 拿合切跑一遍 refscan，硬引用跟 `落空白名单.json`（这一回的 41 处，第一次跑时写出来）比，多出来的停下报给人看。
   - 拿 slim_card.cases 的两百多种凭证和回复底座，模拟一遍 DLC 条目还醒不醒得了（这一包里每条至少在一种凭证下醒），跟 prompt_stage1.check 一个路数。
7. **清单**：`DLC/清单.json` 记每包的条数、字节、sha256、**指纹**（各条 norm 以后排序再取 sha256）、版本、对应的本体版本；`DLC/说明.md` 写怎么建模组（下一节）。zip_cards 加一个 `--dlc`，把 DLC 目录打成 `奥尔德兰_四纪大框_DLC.zip`。

### 稳（模组更新不会自动推给玩家）

玩家装了哪一版就一直是哪一版，要自己去选新版本再保存。所以：

- **DLC 的条目尽量冻住**。make_dlc 每回拿这一回的指纹跟 `底稿/DLC/发布记录.json` 里上一回发出去的比，一样就不出新版本；变了列出增、删、改各几条，由人定要不要发新版。错字级别的小改攒着，攒够了一起发。
- **DLC 靠本体的几样接口**，本体往后改这几样，旧版 DLC 就静悄悄地醒不了：
  - 凭证和底座里的 `纪元：X纪N年`（DLC 的触发和黑名单里一共用了两千三百多回：羁绊 1347、支线 520、神谱 281、大图书馆 178）；
  - 纷争纪二十二张那一路的 `开局时段：第二十二张｜年份：N`（羁绊 124、支线 81）；
  - 人名、地名、章名、书名本身（羁绊的触发认“X的个人线”“章名”，旅伴、神改了名，旧 DLC 认不出）。
  - 这几样写进 make_dlc 的核：本体的凭证格式（slim_card.cases）一变，DLC 模拟醒不了就停。改人名的时候 rename_stars、换名脚本跑完要看 DLC 那几包有没有跟着变，变了就是要发新版。
- 本体只拿掉、不改写 DLC 的条目，玩家装着旧版 DLC 也不会跟本体打架；唯一会重的是玩家还在用切包以前那一张全本卡又装了 DLC，说明里写一句。
- 文件夹名照旧（`57·月银纪｜羁绊`……），装上以后在世界书里跟本体各归各的文件夹，玩家一眼看得出是哪一包来的。

### 风月那一头

风月没有模组，风月版照旧从 `_全本.json`（或者直接从 v12）出，DLC 的内容并进卡。照 `风月版_方向稿.md` 第二版拆三张，向着黎明（月银纪加纷争纪，估 4070 条）、旅印·上（山铜纪加前传，估 4215 条）本来就把这些算在里头，离 5000 条的硬线还有七八百条的空，不用另拆。真到了某一张超线，四包按大小可以拿掉（向着黎明里羁绊 263、支线 103、神谱 216、配套史诗战 15；旅印·上里羁绊 277、支线 113），大图书馆进哪一张都行。1001 年切片照旧不带这些。

## 四、发布设置的建议

模组建了以后适用范围、公开、收费改不了，一天至多新建五个，发公开模组要有充值记录或积分过十五万（先请用户看账号够不够）。

- **先私密试一个**：拿最大的羁绊篇（2.97MB、540 条）建一个私密的卡片专用模组，导进来看编辑器认不认这么大的、装上以后条目数对不对、存不存得上，跟本体一起醒得对不对（月银纪局里问希尔妲的个人线、纷争纪二十二张那一路问一位旅伴的章名）。私密的改不成公开，试完删掉，正式的另建。
- **正式的**：卡片专用（绑公开的那一张，别绑测试链接那一张）、免费、公开，四包四个，一天建得完。
- **标题**：`奥尔德兰的旅印·羁绊篇`、`奥尔德兰的旅印·各地支线`、`奥尔德兰的旅印·神谱`、`奥尔德兰的旅印·大图书馆`。平台标题上限没量过，十二个字以内稳。
- **描述**（照这个样子，四包各改内容那一句）：
  > 版本 11-24｜对应本体 11-24 起｜世界书 540 条，追加进本体
  > 四个纪元的旅伴和传奇各自的羁绊之章：问起一个人的个人线、说出章名、或者他自己开口邀你，那一章才开。不装也能玩，旅伴照常同行、好感照常记，只是不开章。
  > 更新：模组出了新版本不会自动换，到模组那一栏选新版本再保存。别跟旧的整张卡（世界书八千五百多条的那一张）一起用，会重两份。
- 版本号写进描述的头一行，跟 make_dlc 清单里的版本、本体发布说明里的版本对得上；用户在模组的版本说明里也写同一个号。
