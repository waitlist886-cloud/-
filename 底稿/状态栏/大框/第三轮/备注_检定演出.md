# 备注：检定演出（11-23，状态栏第三轮）

模块 `底稿/状态栏/大框/judge_fx.py`（RULES 五条、css()、check() 数量词）。直接跑它就导出 `第三轮/检定演出_rules.json`、`第三轮/检定演出.css`，再带一个路径参数另写一份插好了的整套规则（复刻台用）。出图脚本 `底稿/状态栏/大框/judge_art.py`，样本脚本 `第三轮/检定演出_造样本.py`。

## 一、记录行

```
§判｜类·事｜出手方全名 位阶·能级 LVL n｜出手方的几项｜应对方全名 位阶·能级 LVL n｜应对方的几项｜定档｜第几颗 n｜结果｜一句后果
```

例：

```
§判｜攻防·横断劈开枪阵｜洛恩·维斯特 共鸣·凝华 LVL 38｜STR 46↑、ATK 96↑、Skill 长剑·共鸣7阶↑、伤 左臂轻伤↓｜骸骨枪卫 共鸣·圆满 LVL 34｜VGR 38、PV 52↓、DV 21、地形 枪阵封住回廊↑｜五五｜第二颗 17｜暴击｜剑从肘节劈进去，枪卫 HP −148，架势 −40，下一个交锋先手归你
```

定下来的几件：

- 十栏，分隔只有全角竖线一种；一栏里的几项用顿号；一项是「类 名或数」，末尾 ↑ 是这一下里帮了他，↓ 是拖了他，不好不坏的不带记号。逗号、加减号、三角（，,＋+－-▲▼）也认。
- **谁出手谁写在前头**。出手方是动手、开口、去做的那一边，应对方是挨这一下、被说动、被瞒过的那一边；敌人打主角就是敌人在前。这样矛总在左、盾总在右，展开的时候不用猜谁攻谁守，对冲的条也只用认一个方向。
- 骰把结果挪了几格**不让模型写**：档位尺上定的那一格、挪到的那一格、骰旁那一句（好一档、坏一档、照定的那一档、大成功、大失手）都由样式照定档和骰点算（1 到 5 坏一档，6 到 15 照定的，16 到 20 好一档，两头夹在五格里），少一处会写歪的地方。
- 结果词两套各六个。战斗照骰：大成功、暴击、打实、擦中、落空、大失手。别的事照挪过以后落在哪一档：稳和有利写 成了，五五写 险成，不利写 差一点，几乎不可能写 没成，掷出 20 写 大成，掷出 1 写 砸了。认字眼，写了别的词照中等的样子出。
- 字数：提示里说九十字上下。两边都带位阶·能级和 LVL 的话，名字那两栏就占四十来字，再各写三项、一句带数的后果，实际一百一十到一百三十字；样本里为了把各种小标都亮出来写到了一百五六十字。骨架的话里我写的是“一边二到五项，整行一百一十字上下”。要压到九十，把位阶·能级拿掉只留 LVL，规则不用改（名字后头那一段是整段照抄的）。

## 二、要添进骨架的原话

接在③那一段讲 §技、§起手 的话后头（“……寻常的砍、挡、跑和不要紧的判定照旧写在段落里。”之后）：

> 要紧的检定，结果落下来的那一处另写一行 `§判｜类·事｜出手方全名 位阶·能级 LVL n｜出手方的几项｜应对方全名 位阶·能级 LVL n｜应对方的几项｜定档｜第几颗 n｜结果｜一句后果`，十栏，栏序不变。只给这一轮定输赢的那一下：一场仗里要紧的一击，交涉、潜行、察觉、追逃里定成败的那一回，一轮至多两行；别的检定照旧只记在 §推演｜6，不写这一行。类写 攻防、交涉、潜行、察觉、术式、追逃、开锁、攀爬、意志 这样两个字，事写四到十个字。出手方是动手、开口、去做这件事的那一边，应对方是挨这一下、被说动、被瞒过的那一边，谁出手谁写在前头，敌人打主角就是敌人在前；名字后头空一格写位阶·能级和 LVL，照面板和角色卡抄，摸不清的写 约 LVL n。应对的是一道难处（一把锁、一面墙、一场暴风雪）就只写它的名字，空一格写一句难在哪，它那一栏的几项写 无。几项是这一下真用上的东西，一边二到五项，一项写成「类 名或数」，顿号隔开，这一下里帮了他的末尾加 ↑，拖了他的加 ↓，不好不坏的不加：头一项写主项属性（STR 46），往后从这些里挑用上的写，ATK 或 MAG、PV、DV 的数，抗 加元素和数（抗 火 20%），元素 加这一下带的属性（元素 霜），Skill 名·熟练度，Art 名·几阶，Active、Passive、命星 名·稀有度，装备 名·品阶，专长 名，增益、减益、伤、状态 名，地形、准备、位阶、人数 后头一句四五个字。数照面板和角色卡抄，不现编，不凑数；攻防的那一下，出手方写上 ATK（放术写 MAG），应对方写上 PV 和 DV。定档照 §推演｜6 定的抄，写 稳、有利、五五、不利、几乎不可能 里的一个。第几颗 n 写用的是这一轮第几颗命运骰和它的点数（第二颗 17），六颗用完、照实力直接判的写 无；骰把结果挪了几格不用写。结果写一个词：战斗里照骰写 大成功、暴击、打实、擦中、落空、大失手；别的事照挪过以后落在哪一档写，稳和有利写 成了，五五写 险成，不利写 差一点，几乎不可能写 没成，掷出 20 写 大成，掷出 1 写 砸了。末一栏写这一下的后果，带数：伤害、架势、位置、谁拿到下一轮的先手、对方让了哪一步。一边二到五项，整行一百一十字上下，值里不写竖线和引号。同一下既放了有名字的招又是要紧的检定，§技 在前、§判 在后，§技 那一句写看得见的事，§判 的后果写数，两句不重样；有对手的技能判定写 §判，不再另写 `§技｜…｜Skill` 那一条。

四纪大框的主提示词不读骨架，`four_era_prompt.py` 的 SYS_EDITS「正文」那一条要添同样的一段。月银纪、纷争纪早年没有命路的局，几项里照那一纪的叫法写（法门、兵器加风格），栏不变。

## 三、「检定与命运骰」那一句怎么改

原句：

> - 骰值只写在推演和战斗栏里。正文写成看得见的事（脚下一滑，剑擦着肩过去），不报数，不写运气两个字。

改成：

> - 骰值写在三处：§推演｜6，战斗栏，和正文里那一行 `§判`（只给这一轮要紧的一两下，写法见骨架③）。`§判` 是界面上的一张面板，不算叙述，它的定档、骰点、结果照 §推演｜6 那一段抄，三处对得上。段落照旧写成看得见的事（脚下一滑，剑擦着肩过去），不报数，不提骰子和档位，不写运气两个字。

## 四、§战况｜检定 留不留

留，分工是这样：

- `§推演｜6` 的检定一栏是底账，这一轮所有检定都在这里，面板和战斗栏都照它抄。
- `§战况｜检定` 是交战那一页里的流水：战斗轮每一次命中、闪避、格挡一行，短（谁对谁·定的档·第几颗骰 n→结果），翻战斗页的人对账用。只有战斗轮有。
- `§判` 是正文里的演出：一轮至多两张，只挑要紧的那一下，把两边拿来比的东西亮出来。交涉、潜行这些不开战斗栏的轮次只有它。

写了 §判 的那一下，§战况｜检定 那一行照写（二十来字），不然战斗页的流水里正好缺最要紧的一击。嫌重复的话可以把 01_角色声明 那一句改成“写了 §判 的那一下，§战况｜检定 不再写”，显示层两种都不用动。

## 五、规则

五条，量词最多的一条二十四个（平台上限二十五，惰性的问号算一个，照 check_card.mjs 的数法），没有量词套量词，没有后顾。

| 名字 | 做什么 |
|---|---|
| 判 | 十栏对得上的，展开成整张面板。两边的几项各放进一个壳（`<s class="jg-f">`、`<del class="jg-f">`），前头留记号 ⓗ |
| 判·简 | 栏对不上的（少了一边的几项、多了一栏），只认开头的类·事和末尾的定档、骰、结果、后果，出简版 |
| 判·主项 | ⓗ 往后看两个壳：两边的主项属性（两个大数），出手方的 ATK 或 MAG 对应对方的 PV（对冲的条）。换成 ⓘ |
| 判·对 | ⓘ 往后看两个壳：出手方的 Skill 对应对方的 DV，出手方的元素对应对方的抗性（两对并排的牌） |
| 判·拆 | 两个壳里的几项一项一项拆成小标，壳尾的记号 ⓕ 换成一枚不显的空小标 |

**接在哪**：插在 `make_rules_frame.py` 的 `rule('技·没写完', …)` 后头、`rule('话·冒号', …)` 前头（现在的第 75 条和第 76 条之间）：

```python
import judge_fx as _JG
for _n, _rx, _rep in _JG.RULES:
    rule(_n, _rx, _rep)
```

不能接在整套后头：§判 行到「记录兜底」就被收成一行字了。也不能挪到队友浮栏那一组前头：浮栏的「增益·拆」「减益·拆」认的是 `</s>`、`</del>` 前头的顿号，会把这里两个壳里的几项当成增益拆掉。反过来不会：这里的壳末尾带一个记号 ⓕ，「判·拆」只拆后头跟着 ⓕ 的顿号，别的模块拿 `<s>`、`<del>` 当壳的不受影响；「判·主项」「判·对」也只认紧跟着 `<s class="jg-f">` 的 ⓗ、ⓘ。三个记号 ⓗ、ⓘ、ⓕ 大框里没用过，五条跑完不留。

样式接在 `make_css_frame.py` 里 rite_fx 那一段后头（`import judge_fx; w(judge_fx.css())`），六万八千字上下，其中小标和徽记的四十来个图形两万字。

## 十、写歪了怎么兜

- 顿号写成逗号、↑↓ 写成加减号或三角、定档那一栏写了“定档 五五”、骰那一栏写了“骰 第二颗 17·好一档”、栏头多一个空格：照常出整张。
- 少了一边的几项、少了谁对谁、多了一栏：出简版，只有类·事、档位尺、骰、结果、后果。
- 骰写 无 或者没写点数：不出骰子，尺子上只亮定的那一格，旁边写“没有掷骰 · 照实力直接判”。
- 应对方的几项写 无：那一列空着。
- 没写 ATK 或 PV 的：不出对冲的条，写了的那一样照常是一枚小标；主项、Skill 对 DV、元素对抗性同理。
- 一项没写类（先手↑、站在台阶上↑）：整个当名，图形照字眼认，认不出的是一枚菱形。
- 只写了半截、定档不在五个词里、事超过四十字：落到大框原有的「记录兜底」，原样一行字（样式里把这一行收成一条细条）。流式写到一半的时候也是这个样子，写完那一刻换成面板。
- 样本 `第三轮/样本_检定演出_写歪.txt`，截图 `写歪了的兜底.jpg`。

## 十一、验了什么

## 十二、没做成的、要留意的

- 日里真页面、真模型都没上过：模型肯不肯照十栏写、两边的数抄得对不对、一轮会不会写多，要玩一两轮看。
- 面板高（电脑上 480 到 610px），一轮两张加上起手框和横幅会很长，所以骨架的话里卡了“至多两行”。
- 主角那一边的头像没接主角立绘。
- 对冲的条只画了“ATK 或 MAG 对 PV”这一条是按数的比例画的；命中对闪避、元素对抗性是并排的两块牌，没有比大小（Skill 的熟练度和 DV 不是一种数）。
- 小标悬上去没有小卡（一枚小标就是一句话，没有别的可看）。
- 指针和亮格的位置用了 `clamp()` 套 `calc()` 里的自定义属性，Chrome 和新一点的 Safari 都认；很旧的内核上指针会停在最左一格，别的不受影响。
- 额度：Codex 出了四张，没碰到用完。
