# 风月探针第二轮：把“条数”和“字节”拆开测（11-23）

头一轮乙（8440 条、40MB）导入时 normalize 那个请求一直挂着。挂住的缘故有两种可能：条数太多（八千多条钥匙），或者文件太大（40MB）。这一轮三张各测一样，都以线上那张风月底卡为底，照旧不能玩、测完删。

照这个先后测，哪一步有了结论就可以停：

1. **己**（`探针己_全量条数_正文截短.json`，9MB 上下，跟线上那张差不多大）：8440 条全在，正文每条只留 60 字。
   - 导得进、存得住 → 条数不是问题，卡在字节上。接着测 3。
   - 还是挂着 → 卡在条数（或者钥匙）上。接着测 2。
2. **壬**（`探针壬_半量条数_正文截短.json`，6MB 上下）：4220 条、正文截短。己不行才测。
   - 行 → 条数的线在四千到八千之间。
   - 不行 → 线在四千条以下（线上那张是 1427 条）。
3. **丁**（`探针丁_四分之一量.json`，13MB 上下）：2110 条、正文照旧。己行才测。
   - 行 → 再测头一轮的丙（23MB）。丙也行的话线在 23MB 到 40MB 之间。
   - 不行 → 字节的线在 9MB（线上那张）到 13MB 之间。

每一步告诉我：导入成没成、保存成没成、挂着的话等了多久、开发者工具里那个请求是一直 pending 还是回了错（回了错的把状态码和提示发我）。
